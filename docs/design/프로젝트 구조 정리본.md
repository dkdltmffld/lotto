# 프로젝트 구조 정리본 — 고도엔진 기초로 읽기

> 작성: Claude (2026-06-23). 코드베이스 전체 아키텍처를 Godot 기초 개념에 얹어 설명하는 온보딩 문서.
> "현재 기준"만 서술한다(전환/비교 narrative 없음). 세부 수치·결정 이력은 CLAUDE.md Decision Log 참조.

---

## 0. 먼저, 고도의 7가지 기초 (이것만 알면 다 읽힘)

| 개념 | 한 줄 | 이 프로젝트에서 |
|---|---|---|
| **노드(Node)** | 기능 한 조각(레고 블록). 스프라이트·버튼·라벨… | Player, ScratchCard, 라벨 전부 노드 |
| **씬(Scene/.tscn)** | 노드를 트리로 조립·저장한 것. 재사용 부품이자 화면 | `login.tscn`, `main.tscn`, `enemy.tscn` |
| **씬 트리 + 메인 루프** | 실행 중 살아있는 노드들. `_ready()`(태어날 때 1회)·`_process(delta)`(매 프레임)·`_input()`(입력) | `game.gd`의 `_ready`/`_process`가 게임을 굴림 |
| **스크립트(GDScript)** | 노드에 붙이는 "행동". `extends Node` | `game.gd`가 `main.tscn` 루트에 부착 |
| **오토로드(싱글톤)** | 씬이 바뀌어도 **항상 떠있는 전역 노드**. 게임의 뇌·장기기억 | BackendService·Audio·Events·UIManager·NotificationManager |
| **시그널(Signal)** | "무슨 일이 일어났다"는 방송. 관찰자 패턴 | `card_completed`, `died`, `Events.currency_changed` |
| **Control vs Node2D** | UI(앵커 레이아웃) vs 게임 월드(좌표) | HUD·패널=Control / Player·Enemy=Node2D 계열 |

여기에 **Tween**(값을 부드럽게 변화 = 애니/연출), **AnimatedSprite2D**(스프라이트 시트 애니), **리소스/데이터**(JSON)만 더하면 된다.

## 1. 게임이 켜지는 순간 (부팅 → 로그인 → 게임)

`project.godot`이 부팅 순서를 정한다:

1. 엔진이 **오토로드를 먼저 켠다**(게임의 "뇌"). 이때 `BackendService`가 세이브를 로드한다.
2. `run/main_scene = login.tscn` → **로그인 화면**이 첫 화면.
3. 계정 선택 → `change_scene_to_file`로 **`main.tscn`(게임 본체)** 전환.

핵심 설정값(project.godot):
- 해상도 **360×780 세로**, `stretch=canvas_items`(비율 유지 확대), `orientation=portrait`(세로 강제)
- 렌더러 `gl_compatibility` = **WebGL2**(웹 호환의 핵심)
- 한글 폰트(`korean.ttf`) 전역 테마, `emulate_touch_from_mouse=true`(마우스=터치 통일)
- `MCPGameBridge` 오토로드는 게임 로직이 아니라 개발 도구(godot-mcp) 브릿지

## 2. 큰 그림: 두 층 (뇌 / 화면)

```
┌─ 항상 떠있는 "뇌" (오토로드 / 씬 전환에도 안 죽음) ─────────────┐
│  BackendService        세이브·재화·로그인 (단일 진실의 원천)   │
│  Audio                 효과음·BGM                              │
│  Events                전역 이벤트 방송국 (시그널 버스)        │
│  UIManager             패널 열고 닫기 담당                     │
│  NotificationManager   토스트/알림 한 통로                     │
└────────────────────────────────────────────────────────────────┘
        ▲ 게임이 이 뇌들을 호출/구독
┌─ 화면 (씬 — 지금 떠있는 노드 트리) ────────────────────────────┐
│  login.tscn  ──change_scene──▶  main.tscn (game.gd가 지휘)      │
└────────────────────────────────────────────────────────────────┘
```

**핵심 원리**: 화면(씬)은 갈아끼워져도 뇌(오토로드)는 안 죽으니, **상태는 전부 `BackendService` 한 곳에** 둔다. 다른 곳은 값을 들고 있지 않고, 변하면 `Events`로 "변했다"만 방송한다.

## 3. 화면 한 장의 속 (main.tscn 노드 트리)

```
main.tscn (루트 Control + game.gd)    ← 지휘자 스크립트가 여기 부착
├─ ParallaxBackground                 배경 스크롤 (맨 뒤)
├─ Arena (Control)                    전투장
│   └─ Player (AnimatedSprite2D + player_controller.gd)
│       └─ (코드로 생성되는) 적/이펙트가 여기 add_child
├─ ScratchCardArea
│   └─ ScratchCard (scratch_card.gd)  ← scratch_card.tscn 인스턴스
└─ TopHUD / 라벨들                    골드·다이아·스테이지·설정 등
```

특징: `enemy.tscn`/`hp_bar.tscn`/`scratch_card.tscn`은 **거의 빈 껍데기**다. 격자·체력바·적 외형은 스크립트가 런타임에 코드로 만든다(`scratch_card._build_cells`, `enemy._build_animations`). 강화/상점/유물 등 패널은 .tscn 없이 **100% 코드 생성**한다.

## 4. 지휘자 `game.gd` (god object)

`main.tscn` 루트에 붙은 ~2160줄짜리 거대한 지휘자. 거의 모든 흐름을 조율한다. 책임 영역:

- **상태 전이**: `_enter_idle()` / `_enter_run()` (멈춰 싸우나 / 달려가나)
- **적 웨이브**: `_spawn_next()` → `_make_wave_enemy()` → `_clear_wave()` (적 2~4마리 줄지어 등장)
- **전투 2레이어**: `_auto_attack()`(평타, 타이머) + `_on_card_completed()`(스크래치=스킬) → `_skill_multihit()`(잭팟=무리 전체 다타격)
- **진행**: `_on_enemy_died()` → `_advance_stage_after_kill()` → `_finish_wave_clear()`
- **사망**: `_on_player_died()` (보스에게 죽으면 블록 소폭 후퇴)
- **던전 모드**: `_enter_dungeon()` 등 (같은 화면을 `Mode.DUNGEON`으로 분기)
- **HUD 빌드**: `_build_top_bar()` / `_build_nav_dock()` / `_build_stage_banner()` / `_refresh_hud()`

`_process(delta)`(매 프레임)에서 적 전진·자동공격 타이머·HP 자동재생을 돌리고, **시그널을 구독**해 반응한다(스크래치 `card_completed`, 적 `died`, `Events.*`).

> 너무 커서 HUD 빌더 분리 등 일부 떼어내기가 보류 과제로 남아 있다(god object 티어3).

## 5. 데이터는 따로, 로직은 코드 (YAML→JSON 파이프라인)

고도는 YAML을 기본 지원하지 않고 웹에선 더 까다로워서 **자체 변환 단계**를 둔다:

```
data/src/*.yaml   (주석 달린 원본 — balance, upgrades, equipment, relics, quests_*, dungeon, enemies…)
      │  tools/build_data.gd  (직접 만든 YAML 서브셋 파서 + 검증 게이트)
      ▼
data/*.json       (게임이 읽는 산출물)
      │  GameData.table("balance")   ← 1회 로드 후 캐시 (game_data.gd)
      ▼
게임 코드가 사용
```

**경계**: 숫자·표·카탈로그만 데이터로 빼고(코드 수정 없이 밸런스 튜닝), **규칙/로직은 코드**(사망→블록 복귀, 보스 게이트, 족보 공식). `GameData`는 `table()`/`subtable()`/`ordered_ids()`/`weighted_pick()` 공용 헬퍼를 제공.
- ⚠️ `data/*.json`은 비리소스라 웹 export에 자동 포함 안 됨 → `export_presets.cfg include_filter="data/*.json"` 필요(설정됨).

## 6. 성장 콘텐츠 = "계산기 클래스"

`Upgrades`, `Gacha`, `Relics`, `Mailbox`, `Quests`, `DungeonData`, `HandEvaluator` 등은 **노드가 아니라 순수 계산기**(`class_name` + `RefCounted`/static):

- `GameData`(JSON)를 읽어 **계산만** 한다(강화 비용/값, 가챠 등급 추첨, 유물 효과, 족보 평가, 던전 층 스탯…).
- 오토로드를 참조하지 않아 **헤드리스 단위 테스트가 가능**하다(`tools/tests/`).
- **값 저장**은 `BackendService`, **호출**은 `game.gd`/패널이 한다.

예) `HandEvaluator.evaluate()`: 9칸 숫자 → 같은 숫자 매칭 그룹을 세고 **배율 = count² × value** 반환. 와일드(★)·포커식 그룹 랭킹도 여기.

## 7. UI 패널 시스템 (상속 + 등록 + 구독)

강화/장비/유물/상점 패널은 세 가지 고도 기초로 묶인다:

1. **상속**: 전부 `panel_overlay_base.gd` 상속 → 공통 골격(배경·여백·탭/닫기 버튼·토스트) 물려받음.
2. **등록(register)**: `UIManager.register_band_panel(id, panel, host)` → 매니저가 부착·상호배타 오픈 관리. 패널이 씬 소속이라 `tree_exiting`에서 자동 등록 해제(autoload가 죽은 노드 붙들지 않게).
3. **구독**: 패널은 `game.gd`를 모른다. 대신 `Events.currency_changed` 등을 구독해 스스로 갱신(점대점 배선 제거).

`nav_dock`(하단 5탭: 강화/장비/유물/던전/상점) → `UIManager.open(id)` → 해당 패널만 표시. 설정/치트는 전체화면 오버레이(`register_overlay`/`open_overlay`).

## 8. 한 판이 흐르는 과정 ← 전부 꿰는 부분

```
① 부팅 → 오토로드(뇌) 깨어남 → BackendService 세이브 로드 → 로그인 화면
② 계정 선택 → change_scene → main.tscn
③ game.gd._ready(): HUD·내비·패널 짓고, ScratchCard/Player 연결, 시그널 구독
④ 매 프레임 _process(): 적 웨이브 접근, 스크래치 자동 긁힘(scratch_card._process), 자동 평타 타이머
⑤ 9칸 완성 → ScratchCard가 [card_completed] 시그널 방송
⑥ game이 받아 HandEvaluator로 족보 계산
     스킬 데미지 = 공격력 × 족보배율(count²×value) × (1+무기 보너스)   (폭발)
     평타는 공격력만 / 잭팟이면 무리 전체 다타격
⑦ enemy.take_damage() → effects가 빨간 숫자·슬래시(Tween)
⑧ 적 HP 0 → [died] 시그널 → game._grant_gold() → [Events.currency_changed] 방송
⑨ HUD가 구독 중이라 골드 갱신 / 다음 적 or 다음 스테이지
⑩ 골드로 강화 → Upgrades 계산 → BackendService 저장 → [Events.upgrade_purchased] → 스탯 반영
⑪ 10층마다 보스: 보스가 PC 공격[attacked_player] → PC 죽으면 _on_player_died()로 블록 소폭 후퇴
⑫ 저장: 이산 이벤트(강화 등)는 즉시 / 골드 수입은 15초마다·탭 닫을 때
        (웹·비웹 모두 user:// 로컬 파일, 구글/게스트 슬롯 분리)
```

이 한 흐름에 **씬·노드·`_process`·시그널·오토로드·Tween·데이터**가 전부 한 번씩 등장한다.

## 9. 한 장 요약

- **뇌(오토로드)** = 항상 떠있고 상태/세이브/이벤트/UI/소리 담당. 진실의 원천 = `BackendService`.
- **화면(씬)** = login → main, 지휘는 `game.gd` 한 명(거대 god object).
- **소통** = 직접 호출 대신 **시그널**(`card_completed`/`died`/`Events.*`)로 느슨하게 연결.
- **데이터/로직 분리** = 숫자는 YAML→JSON, 규칙은 코드.
- **콘텐츠 로직** = 노드 아닌 순수 계산기 클래스(테스트 쉬움).
- **UI** = 베이스 상속 + UIManager 등록 + Events 구독.
- **웹 제약** = WebGL2·`user://`·브라우저 IndexedDB 격리. 외부 인증·클라우드 브릿지는 없다.
