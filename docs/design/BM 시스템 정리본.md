## 1. 개요

**BM 채널은 둘이다.** ① **자동 긁기 속도 광고 버프 / 광고제거 IAP**(아래 §2~§3, 초반 리텐션과 한 메커니즘으로 묶는 방치형 표준 루프) + ② **소환(가챠) = 다이아 기반 확률 뽑기**(=BM 기둥 → §4 소환 시스템).

- 타겟: HTML5 / kplay.games 배포 (웹).
- 성격: **광고 루프는 비-사행성**(확률 요소 없음 — 단순 속도 버프), **장비 가챠는 확률형**(희귀도 가중 뽑기 = BM 기둥). 유물 복권 가챠([[족보 스킬 시스템 정리본]] §5)와 별개.

## 2. 코어 BM 루프 (3단계) ✅(방향)

1. **맛보기 (Taste)**: 자동 긁기의 **최대 속도**를 **비교적 초반에** 플레이어에게 한 번 경험시킴. → 파워의 도파민으로 수요 창출.
2. **광고 버프 (Rewarded Ad)**: 이후엔 그 최대 속도를 **광고 1회 시청 시 N분 지속** 버프로 제공. → 복귀·세션 리텐션 + 광고 수익.
3. **IAP 전환 (Remove-Ads)**: 추후 **"광고 제거 패키지"**(프리미엄)로 유도 — 광고 없이/영구로 누리게 해 결제 전환.

> 흐름: 맛보여 도파민 → 빼앗음 → 광고/결제로 되찾게. (rewarded boost + remove-ads = 방치형 정석)

## 3. 자동 긁기 최대속도 (대상 메커니즘)

- **`auto_speed`(자동 긁기 속도)는 이미 구현된 복권 성장 축**이며 **상한(cap)이 있다**([[강화 시스템 정리본]] / [[스크래치 시스템 정리본]] §7).
- **버프 = 강화 레벨과 무관하게 자동긁기 속도를 임시로 cap(또는 그 이상)까지 끌어올림.** game.gd가 `scratch_card.auto_rate`에 반영하는 지점에 "버프 활성 시 max" 분기를 얹으면 됨.
- ⏸ **"최대 속도" 정의**: 업그레이드 cap과 동일? 그 이상(전용 부스트 값)? 정해야.
- ⏸ 맛보기 시점(초반 어느 지점에 1회), 버프 길이 N분, 쿨다운, 하루 시청 상한.

## 4. 소환(가챠) 시스템 ✅(UI 구현, 2026-06-09) — BM 기둥

> 장비 등을 **다이아로 뽑는** 확률형 소환. BM의 두 번째 기둥(광고 루프와 별개). 레퍼런스 = 슬레이어 키우기 소환 화면(`docs/ref/뽑기 레퍼런스.jpg`).

- **위치**: 상점 > 소환 > 장비 (내비 "상점" 탭 → `ShopPanel`, `scripts/shop_panel.gd`). 패널 레이아웃은 [[UI 시스템 정리본]] §3 참조.
- **구조 = 멀티 풀(데이터 주도)**: 데이터의 `pools` 맵에 풀마다 1개 정의 → 상점 소환 리스트에 풀당 1행(`pool_order`로 정렬). **풀 추가 = 데이터만 수정**(코드 무변경 — 리스트 자동 증가, 캐릭터는 고정·리스트만 스크롤).
  - 풀 항목 = `{name, effect, stat, cost_dia, cost_dia_11, catalog}`. 희귀도 가중치는 풀별이 아니라 최상위 `grades` 맵(전 풀 공용). catalog 항목 = `{name, grade}`.
  - **현재 풀**: `weapon`(무기 소환, 공격력 곱, 다이아 100/1000, 카탈로그 10종) + `armor`(방어구 소환, 체력 곱, 100/1000, 10종). 등급당 2종 × 5등급. 풀 추가 = 데이터(`pools` + `pool_order`)만.
- **뽑기 단위**: **1회 / 11연차**(10+1, 11연차 비용 = 1회×10 → 1회 보너스). 비용 = **다이아**.
- **추첨**: 전역 `grades.weight`로 5등급 가중 추첨(`Gacha._roll_grade`) → 해당 등급 풀 카탈로그에서 무작위 1개. (일반 60 / 희귀 28 / 영웅 9 / 전설 2.5 / 신화 0.5, 잠정.)
- **결과 연출**: **전체화면 팝업**(희귀도색 카드 그리드 — 일반=회 / 희귀=청 / 영웅=보라 / 전설=금 / 신화=빨강. 딤 탭 또는 "확인"으로 닫기).
- **처리 순서**(`shop_panel._do_pull`): 다이아 부족 가드 → `spend_dia` → `Gacha.roll_many(pool, n)`(→ `{item,grade,name,stat}`) → (빈 풀이면 환불) → 각 결과 `BackendService.add_equip(pool, item)`(인스턴스 생성) → `flush`(소환 = 이산 이벤트 즉시 저장) → `currency_changed`로 HUD 갱신 → 결과 팝업.
- **데이터/코드 흐름**: `data/src/equipment.yaml` → `tools/build_data.gd`(검증) → `data/equipment.json` → `GameData.table("equipment")` → `scripts/gacha.gd`(`Gacha`: 등급 가중추첨 + `pool_ids`/`cost`/`cost_11`/`pool_name`/`pool_effect`/`pool_stat`/`roll`/`roll_many`/`equip_bonus`/`enhance_cost`/`item_info` 등) → UI `scripts/shop_panel.gd`(소환) · `scripts/equipment_panel.gd`(인벤토리·장착/강화/합성). 장비 시스템 상세 = [[장비 시스템 정리본]].
- **소환 > 유물 서브탭 = 가루(dust) 유물 가챠**(2026-06-10 유물 패널에서 상점으로 이전; `shop_panel._do_relic_pull` / `_build_summon_relic_view`). 1회/11연, 결과 팝업·`get_dust` 잔액 실시간 갱신(`Events.currency_changed` 구독)은 장비 소환과 공용. 장비 소환과 나란한 별도 소환 채널. 상세 = [[족보 스킬 시스템 정리본]] §5.
- **상점 > 재화 = 유물 가루 구매**(2026-06-17, placeholder 결제=다이아): `relics.yaml dust_shop{amounts,costs}` → `Relics.dust_shop_pack` → `backend.buy_dust_with_dia`. `shop_panel` 재화 탭(보유 표시 + 구매 팩 행). 환율 잠정 1:1, 결제 통화 추후 재검토.
- **placeholder / 미구현**: 소환 레벨·마일리지 진행바, 광고 소환 버튼(광고 SDK 필요), 상점의 패키지 카테고리("준비 중").
- **구분**: 족보 문서([[족보 스킬 시스템 정리본]] §5)의 **유물 복권과 별개** — 장비 가챠 = 능력치+가챠(BM 직결) / 유물 = 빌드 재미·비파워.
- **⚠️ 심의**: 확률형이라 별도 관리 — 무환전·플레이 획득 위주, 표기 투명성 확보 방향.

## 5. 연결 / 의존성

- **⚠️ 선결: kplay.games 보상형 광고(rewarded ad) SDK 지원 여부 확인.** 광고 루프(§2~§3)가 이것에 달림(웹 HTML5 + kplay). 미지원이면 루프 재설계 필요. ([[reference_kplay_backend]] 확장)
- **리텐션**: 광고 버프 = 복귀 유인. [[리텐션 시스템 정리본]](일일·복귀)과 묶어 설계.
- **통화 일반화**: 재화는 `BackendService.get/add/spend_currency(name)`로 라우팅(골드·다이아 별칭 `CUR_GOLD`/`CUR_DIA`). 가챠 비용은 다이아 차감 경로 사용. ([[project_economy_currency]])
