# 백엔드 시스템 정리본

> 리더보드 · 진행사항 저장(클라우드) · 업적 · 로그인. 결정일 2026-05-29.

## 1. 방향

- 직접 서버를 구축하지 않고 **kplay.games 플랫폼 SDK**를 사용한다.
- 우리 HTML5 zip 배포 방식과 호환 (kplay는 "HTML5 게임 zip 업로드 + 리더보드 등 전기능 사용" 지원).
- 문서: https://docs.kplay.games/ — CLI `/guide/cli`, SDK `/monetize/overview`, postMessage 규격 `/monetize/postmessage-api`.

## 2. 게임 코드가 쓰는 단일 창구 — `BackendService` (autoload)

게임은 `BackendService` 싱글톤만 호출한다. 내부적으로 플랫폼에 맞는 Provider를 골라 위임한다.

| 영역 | 메서드 / 시그널 |
|---|---|
| 최초 로드 | `is_ready`, signal `save_ready` |
| 최고 점수 | `get_high_score()`, `try_set_high_score(score) -> bool` |
| 통계 | `get_stat(key)`, `add_stat(key, amount=1)` |
| 재화 | `get_currency(name)`, `add_currency(name, amount)`, `spend_currency(name, amount)` (키 기반 라우팅, `CUR_GOLD`/`CUR_DIA`/`CUR_DUST` 별칭 = gold/dia/dust). **단일 골드 → 키 기반 다중 재화로 일반화**(public API·세이브키 호환 유지). 음수 인자는 거부(획득/차감 오용 방지). |
| 범용 저장소 | `get_value(key, default)`, `set_value(key, value)` (업적 등 프론트 데이터 저장용) |
| 랭킹/로그인 | `begin_login(provider)`, `commit_auth_session(provider)`(이미 인증된 상태에서 인증 계정 진입/변경), `continue_as_guest()`, `logout()`(로컬만), `delete_account()`(로컬+서버), `submit_score(score)`(게스트 no-op), `show_ranking()`, signal `login_changed`/`logged_out`/`account_deleted`/`score_submitted` |
| 영속화 | `flush()` (dirty면 Provider로 저장) |

- 저장 데이터는 메모리(`_data` Dictionary)에 유지하고 **JSON 한 덩어리**로 영속화 (kplay 한도 value ≤10KB).
- 스키마(`_migrate`): `{ version, high_score, gold, dia, dust, dust_boss_max, stage, last_seen, stats{}, equips{weapon:[],armor:[]}, equipped{weapon,armor}, equip_seq, relics[], relic_slots[], relic_seq, achievements{}, settings{}, mail_claimed{}, quests_daily{date,base,claimed}, quests_main_claimed{} }`. **손상/구버전 세이브 방어**: 숫자 키는 `_num_or`(int/float 아니면 기본값), 컨테이너 키는 `_ensure_container`(타입 어긋나면 기본값 복구).
- 골드가 유일 통화는 아니다 — `dia`(다이아, 장비/유물 뽑기 재화)가 2026-06-08 추가. `dust`(유물 가루, 유물 가챠/합성 재화)도 존재. **`dust`(유물 가루)의 정식 획득 = 보스 첫 클리어(2026-06-17)** — `grant_boss_dust(stage)`가 보스 스테이지를 처음 처치할 때 `Balance.boss_dust(stage)`만큼 지급하고 즉시 flush. **재파밍 차단 = `dust_boss_max`**(가루 지급한 최고 보스 스테이지, 진행 선형이라 단일 int; `stage > dust_boss_max`일 때만 지급, `DEATH_SETBACK` 후퇴와 무관). 오프라인 가루는 없음(능동만). ⚠️ **다이아의 본격 획득 곡선은 미설계** — 치트 외에 퀘스트/우편함이 더미로 지급할 뿐(임시, 밸런스 미설계). 가루는 보스 외에 퀘스트/우편함 더미 보조 + 유물 중복 시 자동 환급도 된다. 수치는 더미(밸런스 보류). **장비는 인스턴스 모델(2026-06-09)**: `equips`=종류별 보유 인스턴스 `[{uid,item,level}]`, `equipped`=종류별 장착 uid("" = 미장착), `equip_seq`=uid 발급 시퀀스. (구 `equip_owned{id:개수}` 폐기·교체.) 장착/강화/합성 API = `get_equips`/`get_equipped`/`set_equipped`/`add_equip`/`enhance_equip`/`combine_equips`/`equipped_bonus`. 상세 [[장비 시스템 정리본]].
- **게스트/인증 저장 슬롯 분리 (2026-06-04)**: 게스트와 인증 계정의 데이터가 섞이지 않게 **저장 위치를 슬롯으로 분리**한다. Provider `set_slot(slot, cloud_sync)`:
  - **인증(`auth`)**: kplay `kplay:save_v1`(기존) / 로컬 `user://save.json`. **클라우드 동기**(`storage-set`).
  - **게스트(`guest`)**: kplay `kplay:save_guest` / 로컬 `user://save_guest.json`. **로컬 전용**(클라우드 미전송).
  - 계정 선택 시 슬롯 전환 + 그 슬롯 데이터로 **재로드**: `continue_as_guest`→guest, `commit_auth_session`/로그인 완료→auth.
  - ⚠️ **자동 로그인 게이트**: kplay는 게스트로 시작해도 `user-info`를 자동 전송해 `is_logged_in`을 true로 만든다. `_on_provider_login_changed`는 **account_type이 인증(google/kplay)일 때만** auth 슬롯으로 전환한다 — 게스트/미선택 상태의 자동 로그인은 슬롯을 안 바꿔 **게스트 데이터를 보호**한다.
- **영속화 모델**: 변동 시 `_data`에 반영 + dirty 표시. `flush()` 호출 시 dirty면 Provider로 저장. **진행은 영구적**(리셋/판 폐기 없음 → discard 개념 없음).
- **저장 트리거 (이중)**:
  - **즉시 flush** — 업그레이드·강화·구매 등 **골드를 쓰는 이산 이벤트**(드묾, 유저 액션). 강화·구매가 손실되지 않는다.
  - **묶어서 flush** (연속 골드 수입용) — 주기적(`AUTOSAVE_INTERVAL=15.0`초, dirty면 1회) + 앱 종료/백그라운드 전환 + 오프라인 정산 시. 최악의 경우 크래시 시 몇 초치 골드 수입만 손실(무시 가능).
  - **골드 수입(처치·자동 긁기)마다 저장하지 않는다** — kplay 클라우드 저장(postMessage)을 초당 다수 호출하면 안 됨.
  - `_notification`(창 닫기/백그라운드/PREDELETE)에서 dirty면 best-effort 저장. **웹은 추가로** `visibilitychange`(hidden)·`pagehide`에 best-effort flush(`_setup_web_lifecycle_flush`/`_on_web_hide`) — 브라우저가 종료 알림을 안정적으로 안 보내 ~15s autosave 사이 탭 닫음 시 골드 유실을 줄인다.

## 3. Provider 추상화

- `BackendProvider` (추상) → `load_all()`(코루틴) / `save_all()` / `login(provider)` / `submit_score` / `show_leaderboard` / `clear_local()`(로컬만) / `clear_account()`(로컬+서버).
- **`LocalBackendProvider`** (비웹: 에디터·데스크탑) — `user://save.json` 파일. **완전 동작**. 단일 플레이어라 리더보드/점수 제출은 no-op, 로그인은 개발 편의용 더미 성공(`login_changed(true, "DevUser")`) emit. 슬롯 분리: 인증=`user://save.json` / 게스트=`user://save_guest.json`.
- **`KplayBackendProvider`** (웹) — `JavaScriptBridge` + 주입형 JS 다리(`window.GodotKplay`).
  - 모델: **localStorage가 source of truth**, 클라우드는 로그인 시 한 번 cloud→localStorage 동기화(공식 KPlayAPI `_syncStorageFromServer` 동작과 동일). `storage-load-result.data = { [key]: string }`(값은 문자열), `e.data`는 파싱된 객체.
  - 모든 postMessage/비동기/JS객체 처리는 `_js_helper()`의 JS에 가두고 Godot↔JS는 **JSON 문자열만** 교환 → GDScript의 JS 객체 동적 key 접근 회피.
  - 로그인 시 헬퍼가 클라우드 동기화를 **끝낸 뒤** Godot에 user-info 통지 → BackendService 재로드 시 localStorage가 이미 최신(기기 간 동기화 레이스 해소). 단 동기화에 타임아웃(8초)이 걸려 늦게 도착하면 `storage-resynced` → `resync_needed` 시그널 → BackendService가 `_data`를 다시 읽어 stale 덮어쓰기를 방지(save_ready 재발화 X).
  - **세이브 압축**: 저장값은 `JSON → gzip → base64("z:" 접두사)`로 인코딩(`_encode`/`_decode`, 구포맷 평문 JSON 하위호환). 인벤토리(장비/유물) 성장 시 클라우드 키당 10KB 한도 내 여유 확보. 압축 후에도 10KB 초과면 경고(localStorage는 ~5MB OK, 클라우드 동기만 누락 위험).
  - `save_all` 반환 = **localStorage(source of truth) setItem 성공 여부**(quota/프라이빗 모드 실패를 성공으로 오인 금지) → BackendService `_dirty` 해제가 이 결과에 묶임.
  - `load_all`=localStorage 동기 읽기(+ 디코드), `save_all`=localStorage(+인증이면 `storage-set` 클라우드), `login/submit_score/show_leaderboard` 전송, `user-info`·`score-submitted`·`storage-resynced` 수신 — **전부 구현됨**.
  - ⚠️ **라이브 기능 미검증** — kplay 배포는 여러 차례 완료(프로젝트 `wqTVB0B5_C2e` "복권 키우기", `tools/deploy_kplay.ps1` + 루트 `.kplay.json`, 캐시 버스팅 포함). 다만 실제 클라우드 저장/로그인 라운드트립(새로고침 후 유지·기기 간 동기화)은 아직 미확인. 압축 인코딩(`z:`)·`save_all` 성공 반환·resync 등 웹 백엔드 수정(2026-06-10)도 헤드리스 검증 불가 → 배포본 라이브 확인 필요. 실제 KPlayAPI 버전이 문서와 다르면 `_js_helper` 메시지 포맷 보정.
- 선택 기준: `OS.has_feature("web")`.

## 4. 업적 (프론트엔드 처리 + 백엔드 저장 분리)

- **업적은 프론트엔드 기능.** 백엔드는 결과를 **저장/불러오기**만 한다(전용 API 아님).
- `Achievements`(**scripts/achievements.gd**, 프론트엔드): 조건 판정 + 해금 처리. **카탈로그 데이터는 코드 상수가 아니라 `data/src/achievements.yaml`(원본) → `data/achievements.json`(변환 `tools/build_data.gd`)에서 `GameData.table("achievements").get("catalog")`로 로드**한다(2026-06-05 데이터 주도 전환). achievements.gd는 카탈로그를 보유하지 않고 판정·해금 로직만 담당.
  - 해금 시 `BackendService.set_value("achievements", {...})`로 메모리 반영(영속화는 `flush()` 시), 조회 시 `get_value("achievements", {})`로 불러옴.
  - `BackendService`에는 업적 전용 메서드 없음 — 범용 `get_value/set_value`만 제공.
- 두 갈래:
  - **stat 기반** (처치 수·최고 점수): `Achievements.check_stat_achievements()` → 새로 해금된 def 배열 반환.
  - **이벤트성** (잭팟·포카드): 조건 충족 시 game.gd가 `Achievements.unlock(id)` 호출 → def 반환(새 해금) 또는 빈 {}.
- UI 토스트: game.gd가 위 반환값을 `NotificationManager.achievement(def)`/`achievements(defs)`로 전달 → **전역 알림 매니저(autoload, `scripts/notification_manager.gd`)가 칩 토스트로 표시(여러 개 동시 해금은 큐로 순차)**. (2026-06-11 — 구 print placeholder 해소)
- 현재 카탈로그(`data/achievements.json`): `first_blood`(첫 처치), `kill_50`, `kill_200`, `score_1000`(한 판 1000점), `four_kind`(같은 숫자 4개), `jackpot`(9칸 동일).
- ✅ 라운드트립 검증: unlock → save.json `{"achievements":{"jackpot":true}}` → 재조회 OK.

## 5. game.gd 통합 지점

- `_on_card_completed`: 족보 count ≥9 → `jackpot`, ≥4 → `four_kind` 업적 체크.
- `_on_enemy_died`: `add_stat("total_kills",1)` + `check_stat_achievements`.
- 통계·업적 해금은 메모리에 누적되고, `flush()`는 §2의 이중 트리거(즉시 + 묶음)로 호출된다.
- **랭킹/점수 제출**(`submit_score`)은 현재 비활성 (랭킹 보류, [[게임 컨셉 정리본]] §11).
- **설정 메뉴**(`SettingsPanel`): 메인 메뉴(계정 변경) / 로그아웃 / 계정 탈퇴 접근. 진행이 영구 저장이라 이탈 시 폐기 없음(로그아웃·탈퇴만 세션 리셋).
- 업적 해금 시: `NotificationManager` 칩 토스트(업적명+설명, 큐 순차) 표시 (2026-06-11 구현).

## 6. 검증 상태 (2026-05-29)

- 헤드리스 파싱·autoload 해석 정상.
- 로컬 전 경로 동작 확인: `flush()` → `user://save.json` 기록 (`stats` 등).
- ⚠️ autoload는 `project.godot`에서 `*` 접두사 필요(`BackendService="*res://..."`) — 없으면 전역 식별자로 인식 안 됨.

## 7. 라이브 검증 절차 (웹)

로컬에선 검증 불가 → 배포본에서 아래 기능을 확인:
1. 웹 빌드 + kplay 배포는 `tools/deploy_kplay.ps1`로 완료됨(`.kplay.json` 프로젝트 ID 재사용). 재배포 시 같은 스크립트 사용.
2. 브라우저에서 실행 → 로그인 → 플레이.
3. 확인: ① 새로고침 후 업적/저장 데이터 유지(localStorage) ② 다른 기기/계정 로그인 시 동기화 ③ 콘솔에 `[kplay]`/JS 에러 없음. (점수 제출·리더보드는 랭킹 비활성 동안 보류)
4. 메시지 포맷이 실제와 다르면 `kplay_provider.gd::_js_helper`의 type/필드명 보정.
