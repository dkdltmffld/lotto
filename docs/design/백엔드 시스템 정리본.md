# 백엔드 시스템 정리본

> 실제 서버 없이 동작하는 로컬 저장 계층. 최종 갱신 2026-09-01.

## 1. 방향

- 웹·에디터·데스크탑 모두 `LocalBackendProvider`를 사용한다.
- 외부 인증, 클라우드 저장, 랭킹, 점수 제출은 현재 백엔드 범위에 없다.
- 게임 코드는 autoload `BackendService`만 호출한다.
- 저장은 `user://` 아래 JSON 파일로 이루어진다. HTML5에서는 브라우저가 이 경로를 IndexedDB에 보관한다.

## 2. 저장 슬롯

| 프로필 | 슬롯 상수 | 저장 파일 |
|---|---|---|
| 구글 | `BackendProvider.SLOT_GOOGLE` | `user://save.json` |
| 게스트 | `BackendProvider.SLOT_GUEST` | `user://save_guest.json` |

- `BackendService.continue_as_google()`과 `continue_as_guest()`가 슬롯을 선택한 뒤 `_load()`한다.
- 구글과 게스트는 실행 방식이 같고 파일만 분리된다.
- 구글의 파일명은 기존 로컬 데이터 호환을 위해 `save.json`을 유지한다.

## 3. `BackendService` 주요 API

| 영역 | API |
|---|---|
| 로드 | `is_ready`, `is_fresh_save`, signal `save_ready` |
| 프로필 | `account_type`, `is_guest()`, `continue_as_google()`, `continue_as_guest()` |
| 세션 | `logout()`, `delete_account()`, signal `logged_out`, `account_deleted` |
| 재화 | `get_currency()`, `add_currency()`, `spend_currency()` |
| 통계 | `get_stat()`, `add_stat()` |
| 범용 저장 | `get_value()`, `set_value()` |
| 영속화 | `flush()` |

스키마는 `_migrate()`가 보정한다. 숫자 키는 `_num_or()`, 컨테이너 키는 `_ensure_container()`로 손상된 타입을 기본값으로 복구한다.

## 4. 영속화 정책

- 메모리의 `_data` Dictionary가 런타임 기준이다.
- 변경 시 `_dirty`를 표시하고, `flush()`가 현재 슬롯을 JSON으로 저장한다.
- 장착·강화·구매·보상 수령 같은 이산 이벤트는 즉시 저장한다.
- 골드 획득 같은 연속 변동은 15초 자동 저장으로 묶는다.
- 앱 종료·백그라운드 전환에서 best-effort 저장한다.
- HTML5는 `visibilitychange(hidden)`과 `pagehide`에도 추가로 저장한다.

## 5. 세션과 삭제

- `logout()`은 먼저 `flush()`한 뒤 메모리 세션만 초기화한다. 저장 파일은 지우지 않는다.
- `delete_account()`는 `LocalBackendProvider.clear_current()`로 현재 슬롯만 삭제한다.
- 삭제 후 다른 프로필 슬롯은 그대로 유지된다.

## 6. 업적·장비·유물·퀘스트

이 기능들은 별도 서버 API가 아니라 `BackendService` 스키마 내의 일반 데이터로 저장된다. 각 기능의 판정과 UI는 프론트엔드 스크립트가 담당한다.

## 7. 검증 항목

- 구글·게스트에 각각 다른 진행도를 저장한 뒤 재진입했을 때 섞이지 않는지 확인한다.
- 로그아웃 후 같은 프로필을 선택했을 때 진행도가 유지되는지 확인한다.
- 계정 탈퇴 후 현재 프로필만 새 데이터로 시작하고 다른 프로필은 유지되는지 확인한다.
