# 스테이지 시스템 정리본

> 무한 스테이지 · 블록 · 보스 · 스케일링 · 사망/재시작 · 오프라인 정산. 상위 컨셉은 [[게임 컨셉 정리본]], 전투 메커니즘은 [[전투 시스템 정리본]], 저장은 [[백엔드 시스템 정리본]] 참조.

## 1. 개요

무한 스테이지로 진행하며, 나아갈수록 적이 강해진다. 적 스탯은 개별 데이터로 만들지 않고 **시스템 배율 공식**으로 결정한다(데이터 노가다 없이 무한 확장).

## 2. 블록 / 스테이지 구조

- **블록 = 10스테이지.** 블록 = 스테이지 (10k−9) ~ (10k).
- **일반 스테이지**: **웨이브 N개**(`MOBS_PER_STAGE`) 처치 → 다음 스테이지. 각 웨이브 = **같은 종류 잡몹 2~4마리**(우측에서 대형으로 등장, 앞에서부터 1마리씩 교전, 맨 앞 1마리만 PC를 약하게 공격). 웨이브 전멸 = 진행 1 + 마리당 골드. (보스·튜토리얼은 1마리.) 상수 `game.gd` WAVE_MIN/MAX/WAVE_SPACING.
- **앞 적 처치 시 PC가 짧게 전진**(`_enter_run` 재사용)해 다음 적과 교전하며, 웨이브 내 처치는 스크래치 카드를 잠그지 않아 연속 조작 가능(잠금/초기화는 웨이브 전멸 시).
- **보스 스테이지 = 10·20·30…** (블록의 끝). 치명적 게이트(§4).

## 3. 스케일링 공식

```
적 HP(s)    = ENEMY_BASE_HP × ENEMY_HP_GROWTH^(s−1)     (지수)
골드 보상(s) = GOLD_BASE × GOLD_GROWTH^(s−1)
보스: HP ×BOSS_HP_MULT, 골드 ×BOSS_GOLD_MULT
```
- 플레이어 성장이 지수적(곱연산)이므로 적 HP도 지수 스케일.
- 잭팟(9칸 동일) 처치 시 골드 ×`JACKPOT_GOLD_MULT` 보너스.

## 4. 보스 (치명적 게이트)

- **보스는 치명적으로 공격**한다(공격력 = 스테이지 스케일 `boss_attack_damage`). 일반몹도 공격하지만 보스 대비 빈도·데미지가 현저히 낮다(`mob_attack_damage`, [[전투 시스템 정리본]] §2-2).
- PC HP가 0이 되기 전에 보스를 잡아야 함 = **공격 vs 생존 DPS 레이스**(전투 [[전투 시스템 정리본]] §3-3).
- PC HP = 생존력(캐릭터 성장 축). **보스 진입 시 풀 충전** + **사망→소폭 후퇴 시 풀 충전**. 블록 내(1~9)엔 `hp_regen`(초당 자동회복, **찔끔 유지형** — [[전투 시스템 정리본]] / [[강화 시스템 정리본]])이 일반몹의 찔끔 피해를 상쇄하되, 그를 초과하는 누적 피해는 남아 **HP가 깎인 채 보스까지 간다**(HP 업글 동기 유지). PC HP바 항상 표시.
  - **`hp_regen`은 보스전 중에도 작동**한다(`in_boss` 게이트 없음 = 의도된 동작). 회복량이 작아 보스의 순간딜·연타를 상쇄하지 못하므로 **HP 풀(hp 강화 트랙) 성장이 보스 생존의 진짜 축**으로 유지된다(무한생존 위험 없음). ⚠️ 회복량·비용·상한은 전부 더미·미튜닝 — 현재 더미값은 일반몹 피해 대비 다소 강해 "찔끔"보다 세므로, 적 데미지·보스 HP와 함께 튜닝 시 하향 검토(메커니즘은 확정, 수치만 TBD).
- 승리 → 다음 블록(10k+1) 진행.
- **✅ 보스 첫 클리어 = 유물 가루(dust) 지급 (2026-06-17)**: `Balance.boss_dust(stage) = RELIC_DUST_PER_BOSS_BASE(50) + RELIC_DUST_PER_BOSS_STEP(10)×(블록인덱스-1)`(비보스=0). 가챠 비용이 고정이라 골드식 기하가 아닌 **완만 선형**. **첫 클리어만 지급**(재파밍 차단)은 `backend.grant_boss_dust(stage)`가 세이브 키 `dust_boss_max`로 가드(`DEATH_SETBACK` 후퇴와 무관). 지급 시 `NotificationManager.reward` 토스트 + `Events.currency_changed` + reward 효과음. **오프라인 가루는 없음**. 가루 = 유물 가챠 재화의 정식 주 획득처([[족보 스킬 시스템 정리본]] §5-4 / [[재화 정책 초안]]). 수치 더미.
- **외형**: 현재 더미(1.8배 + 보라 틴트, 발밑 기준 확대로 바닥선 유지). 추후 보스 전용 아트.

## 5. 사망 / 소폭 후퇴

- PC HP 0(보스가 주원인, 일반몹 누적으로도 가능) → `dead` 모션 → **사망 지점에서 `DEATH_SETBACK`(현재 3) 스테이지만큼 소폭 후퇴**. 단 **현재 블록 첫 스테이지가 바닥선**(블록 경계 아래로는 안 내려감).
  - 예) 보스10 사망 → 스테이지7 / 보스20 → 17 / 보스30 → 27. (`Balance.retry_stage(s) = max(block_start(s), s - DEATH_SETBACK)`)
  - ⚠️ 과거엔 **블록 첫 스테이지로 통째 복귀**(보스10→1)였으나, 9스테이지 되돌림이 가혹해 **소폭 후퇴로 완화**(2026-06-16). 블록 farming 루프는 유지(후퇴분 7~9 재진행)하되 슬로그를 줄임.
- **골드·강화는 유지**(영구 진행). **게임오버(영구 종료)는 없다** — 사망은 소폭 후퇴일 뿐.
- **死스파이럴 없음**: 후퇴 구간 잡몹(고스테이지라 골드 수입 큼)을 farming으로 골드를 벌 수 있다 → 강화 → 보스 재도전.
- 후퇴 폭은 데이터값(`balance.yaml stage.death_setback`)이라 밸런스 패스 때 조정 가능.

## 6. 성장 벽 (이중)

- **soft**: 잡몹 HP 성장이 내 DPS를 앞지르면 처치가 느려짐(골드/시간 하락).
- **hard**: 보스를 못 잡으면 사망 → 진행 차단.
- 둘 다 업그레이드 동기를 만든다.

## 7. 오프라인 정산

- 떠난 시점의 **현재 스테이지를 고정 farming**(스테이지 전진 X)으로 누적. `gain = min(offline_rate(stage) × 경과초, 저장소 상한)`.
- → 정산 공식·상한·재접속 주기 상세는 **[[오프라인·방치 시스템 정리본]]**. `offline_rate`/`EST_SECONDS_PER_MOB`는 `balance.gd`.

## 8. 적 외형 = cosmetic (무작위 변종)

- 스탯은 공식이 담당하므로 스프라이트는 스탯과 무관하게 돌려쓴다 → "적 종류 다양화"는 순수 비주얼 작업.
- **스폰 시 외형 변종을 무작위 선택**(일반몹·보스 공통). 스탯·타이밍은 불변, 외형만 바뀐다.
- **웨이브 단위로 외형 통일**: 같은 웨이브 2~4마리는 모두 같은 변종(`Enemy.pick_variant()`를 웨이브당 1회). 보스는 단독·전용 틴트.
  - **폴더 구조**: `assets/sprites/enemies/<id>/<id>_idle.png` + `<id>_attack.png`(가로 스트립). 변종 = 폴더 1개. 현재 `mon_001`/`mon_002`/`mon_003`.
  - **카탈로그 = 데이터 주도**: 변종 목록은 `data/src/enemies.yaml`의 `variants:`(현재 `[mon_001, mon_002, mon_003]`) → `data/enemies.json`. `enemy.gd` `_variant_catalog()`가 `GameData.table("enemies")`로 로드해, 그중 **idle/attack 시트가 모두 로드 가능한 것만**(`_variant_ok`) 추려 무작위 선택. 새 변종 = 폴더(`assets/sprites/enemies/<id>/`) 추가 + `enemies.yaml` `variants`에 id 추가 후 build_data 변환이면 자동 합류. (⚠️ 웹 export에서 `DirAccess` 폴더 스캔은 불안정 → 명시 카탈로그 방식)
  - **프레임 규격**: 폭=256 고정, **높이는 시트마다 다를 수 있음**(idle 256 / attack 256·320 등). 프레임 수 = width/256.
  - **발끝 정렬 + 크기 정규화 = 콘텐츠 스캔**: 시트마다 ①캐릭터 위치(위/아래 패딩)와 ②그려진 크기가 **제각각**이라(같은 몬스터인데 idle↔attack 위치·크기가 다름) 그대로 쓰면 전환 시 튀고 커졌다 작아진다. → `get_image()`로 **프레임별 발끝(불투명 최하단)과 캐릭터 높이(프레임 bbox 높이)의 중앙값**을 구해:
    - **크기 정규화**: `norm = idle 캐릭터높이 / 이 시트 캐릭터높이` → `sprite.scale = 0.35 × norm`. **idle을 기준**으로 attack을 같은 화면 크기로(몬스터 간 고유 크기는 유지, 같은 몬스터의 idle↔attack만 일치).
    - **발끝 정렬**: scale 보정 후에도 발끝이 화면상 같은 바닥선에 오도록 `sprite.offset.y` 계산.
    - ⚠️ **중앙값** 사용 이유: 무기 든 프레임·던진 투사체(예: 바닥까지 내려간 뼈)가 이상치라 시트 전체 최하단/단일 프레임을 쓰면 어긋남. 경로별 1회 스캔 후 static 캐시. 임포트 무손실(`compress/mode=0`)이라 **웹 안전**.
  - **attack 모션**: speed를 windup에 맞춰 자동 계산(프레임 수 무관). **PC 피격 데미지 시점은 `attack_windup` 고정**이라 외형/프레임 수와 무관(보스·일반몹 공통 공격, [[전투 시스템 정리본]] §2-2).

## 9. 데이터 / 코드 위치

- **데이터 원본**: `data/src/balance.yaml`(사람이 편집) → `tools/build_data.gd`로 `data/balance.json` 변환 → 런타임은 `GameData.table("balance")`로 로드.
- **`scripts/balance.gd`**: 위 JSON을 `_static_init()`에서 읽어 `BLOCK_SIZE`/`MOBS_PER_STAGE`/`DEATH_SETBACK`/`ENEMY_BASE_HP`/`ENEMY_HP_GROWTH`/`BOSS_HP_MULT`/`GOLD_BASE`/`GOLD_GROWTH`/`BOSS_GOLD_MULT`/`JACKPOT_GOLD_MULT`/`BOSS_ATTACK_*`·`MOB_ATTACK_*`/`AUTO_ATK_COEF`/`AUTO_ATK_SPEED`/`EST_SECONDS_PER_MOB`/`RELIC_DUST_PER_BOSS_BASE`/`RELIC_DUST_PER_BOSS_STEP` static var에 채운다(JSON 누락 시 코드 기본값 폴백) + static 함수 `is_boss_stage`/`block_start`/`retry_stage`/`enemy_hp`/`gold_reward`/`boss_attack_damage`/`mob_attack_damage`/`offline_rate`/`reward_gold`/`boss_dust`.
- **진행 스테이지 저장**: `BackendService.get_stage()`/`set_stage()`.
- **루프 제어**: `scripts/game.gd` (`_spawn_next`, `_on_enemy_died`, `_on_player_died`).
