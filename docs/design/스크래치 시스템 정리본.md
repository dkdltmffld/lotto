# 스크래치 시스템

> 상위 컨셉은 [[게임 컨셉 정리본]]. 스크래치는 핵심 메커니즘이며 **방치(자동) + 능동(수동)을 동시에 담는 단일 시스템**이다. 전투력 연계는 [[전투 시스템 정리본]] §3.

## 1. 개요

PC 공격은 두 레이어로 나뉜다(2026-06-05 전투 2레이어 전환).
- **일반 공격(자동)**: 교전 중 **고정 주기**(`Balance.AUTO_ATK_SPEED` = `balance.yaml` `auto_attack.speed`, 3.3/초)마다 자동 발동, 데미지 = 캐릭터 공격력 × `AUTO_ATK_COEF`. 데드타임을 없애는 바닥 DPS. (2026-06-15 공격속도 강화 폐지 — 옛 `attack_speed` 트랙의 최대값을 모두에게 기본 제공, 자동 DPS는 공격력으로만 성장.)
- **스크래치 스킬(버스트)**: 3×3 카드의 9칸이 모두 공개되면 족보가 평가되고 강한 한 방(공격력 × 복권 배율 × 족보배율)이 발사된다. 스크래치는 이 스킬 레이어를 담당하며, 일반 공격이 바닥 DPS를 깐다.

스크래치는 더 이상 유일한 공격 수단이 아니라 자동 일반 공격 위에 얹히는 **스킬/버스트** 레이어다. 전투 2레이어 상세는 [[전투 시스템 정리본]] §3.

**복권 한 장은 항상 긁히고 있다.**
- **자동(방치)**: 입력이 없어도 느린 속도로 한 칸씩 자동 공개 → 안 만져도 전투가 진행된다.
- **능동(수동)**: 직접 드래그하면 손가락 속도만큼 훨씬 빠르게 공개된다.
- 둘은 **같은 카드**를 긁는 것이며, 9칸 완료·족보·공격 발동은 동일하다. 능동은 자동 위에 얹혀 진행을 가속한다.

## 2. UI / 그리드 구성

### 2-1. 화면 위치
- 화면 하단 영역(`ScratchCardArea`). anchor·크기는 [[UI 시스템 정리본]] §3 / 본 문서 §8-3.

### 2-2. 그리드 구성 — 3×3 고정
- **3×3 = 9칸 고정.** 그리드 크기 확장(4×4 등)은 보류한다 — 레이아웃·연출·밸런스 리스크가 커서 당분간 3×3 고정(§9).
- 각 셀 구성:
    | 요소 | 구현 | 역할 |
    |---|---|---|
    | 셀 배경 | `Panel` + `StyleBoxFlat` (베이지 바탕 + 어두운 테두리 3px + 라운드 2px) | 긁어낸 후 드러나는 숫자 뒷판 |
    | 숫자 라벨 | 검정 톤, font_size 32 | 1~9(잠정) |
    | sub-cell 덮개 | 코팅 이미지(`assets/ui/scratch.png`) 조각 | 긁기 전 숫자를 덮음 |

### 2-3. Sub-cell (덮개 분할)
- 각 셀 덮개는 **N×N sub-cell**로 슬라이스(코팅 이미지의 `AtlasTexture` region). 브러시/자동이 닿은 sub-cell만 사라져 점진적 제거를 시뮬레이션.
- 기본 분할: **10×10 = 100/셀** (9 × 100 = 900 TextureRect — 웹 성능상 더 키우지 말 것).

### 2-4. 잠금 / 활성 시각
- [[UI 시스템 정리본]] §7-2. 잠금=`LOCKED_TINT`로 카드 전체 어둡게, 활성 진입 시 노란 펑 → 흰색 트윈.

## 3. 스크래치 동작

### 3-1. 능동 입력 (수동)
- **터치(`InputEventScreenTouch`/`Drag`) + 마우스(좌버튼 드래그)** 모두 처리(데스크탑/웹 대응).
- 포인터 이동 궤적을 따라 sub-cell 제거. 카드 잠금 상태면 입력 무시.

### 3-2. 자동 긁기 (방치)
- 입력이 없어도 카드가 **느린 속도로 스스로 공개**된다(한 칸씩 진행).
- **자동 긁기 속도**는 복권 성장 축의 핵심 레버이자 방치 DPS다 — **긴 성장 텀 + 상한** 보유(§7, [[게임 컨셉 정리본]] §6·§8).
- 능동 입력은 자동 진행 위에 **추가로** 얹힌다(능동 중 자동도 계속). 능동이 훨씬 빠르므로 플레이 중엔 능동이 지배적.
- **운(족보)은 자동/능동 무관하게 동일** — 차이는 오직 *분당 완료 수(공격 횟수)*. 능동을 많이 할수록 잭팟 기회도 늘어난다.

### 3-3. 브러시 (능동)
- 브러시 반경(`brush_radius`, 기본 **30px** = 지름 60px) 안에 중심이 든 sub-cell 제거. 판정 `local_pos.distance_to(sub_center) <= brush_radius`.
- 한 이벤트로 여러 sub-cell·여러 셀 동시 긁기 가능. 굵기 조정은 이 값 하나.

### 3-4. 셀 완료 판정
- 셀 "완료" 조건(둘 중 하나, OR) — (a) sub-cell 제거 비율이 **`completion_threshold`(기본 0.7)** 이상, 또는 (b) **칸 가운데 영역(`center_complete_ratio`, 기본 0.5=중앙 50% 정사각)이 다 긁힘**(2026-06-17 추가). 숫자가 칸 가운데 그려지므로 "숫자가 보이는데 완성 안 됨"을 (b)가 해소 — 브러시 반경(30) > 가운데 영역이라 가운데 한 번 긁으면 완성. (b)는 **수동 긁기 전용**(자동은 칸 전체를 한 번에 벗겨 무관). 완료 이후엔 기능상 변화 없음.

### 3-5. 셀 완료 피드백
한 셀이 임계 도달 즉시 동시 발동(자세히는 [[UI 시스템 정리본]] §7-3):
1. 남은 sub-cell 일제 페이드아웃(0.15초)
2. 셀 배경 노란 플래시
3. 숫자 라벨 펑(scale 1→1.3→1)

### 3-6. 9칸 모두 완료
- 9칸 완료 시 `_complete()`가 카드를 즉시 잠그고(`is_locked = true`), `HandEvaluator`가 9칸을 평가해 결과 dict를 `card_completed`로 emit.
- 자동/능동 어느 쪽으로 채워졌든 동일하게 발동.
- `_complete()`는 `is_locked = true` + `card_completed.emit`만 한다. 잠금 해제·새 카드 발행은 `ScratchCard`가 스스로 하지 않고 **`game.gd`가 전투 상태에 맞춰 완전히 소유**한다 — 적 조우 시 `_enter_idle()`에서 해제, 적 생존 시 `reset_card()`로 새 카드+해제, 이동(run)·처치 중엔 잠금 유지.
- **웨이브(잡몹 2~4마리) 잠금 동작**: 웨이브 내 앞 적을 처치해도 카드를 잠그거나 초기화하지 않는다(`_enter_run(false)`) → 다음 적과의 교전까지 카드를 그대로 둬 **연속 조작** 가능. 잠금·새 카드는 **웨이브 전멸 후 다음 웨이브로 이동할 때만** 건다. 스킬 적중 후 새 카드 발행 가드는 **`if current_enemy != null: reset_card()`**(적 생존·웨이브 내 다음 적이 있으면 즉시 새 카드 / 웨이브 전멸=`current_enemy==null`이면 그대로 둠 → 인터-웨이브 `_enter_run(true)`이 잠금+리셋). ⚠️ `is_locked`는 `_complete()`가 완성 순간 항상 `true`로 만들어 이 가드 조건으로 쓸 수 없다(2026-06-09 "긁힌 채 초기화 안 됨" 버그 — `is_locked` 가드는 항상 막혀 적이 죽을 때까지 리셋 안 됨 → `current_enemy` 기준으로 수정).
- ⚠️ 과거엔 `_complete()`가 `lock_duration`(1.0초) 타이머로 자체 해제했으나, 이동 중 재긁힘 버그를 유발해 **`@export var lock_duration`와 자체 해제 타이머는 코드에서 완전히 삭제**됐다(현재 `scratch_card.gd`에 식별자 없음).

## 4. 숫자 / 족보

> **족보 = 같은 숫자 N개 매칭 그룹으로 확정**(2026-06-08, 현행 max-count가 그것). 포커 무늬/슬롯/라인은 검토 후 폐기, 나인 잭팟 유지. 매칭 등급 레벨업은 별도 성장 축([[족보 스킬 시스템 정리본]]).

### 4-1. 숫자 배치
- 각 셀에 무작위 정수, 중복 허용. 새 카드마다 `_roll_number()`로 새로 생성.
- **숫자 분포는 집합/가중치로 커스터마이즈 가능**(2026-06-02): 기본은 `number_min`~`number_max`(1~9) 균등이지만, 런타임에 분포를 바꿀 수 있다.
    - `set_number_weights({값:가중치})` — 가중 추첨. 예) `{7:3, 8:1, 9:1}` → 7이 3배 자주.
    - `set_number_pool([값…])` — 균등 집합. 예) `[7,8,9]` → 7·8·9만 같은 확률.
    - `set_number_range(min, max)` — 커스텀 분포 해제, 균등 범위로 복귀.
    - 변경은 **다음 카드(`new_card`)부터** 반영(즉시 반영은 `reset_card()`). 적용 단일 지점 = `game.gd._apply_scratch_numbers()`(현재 균등 1~9, 강화/등급 연동 훅).
- **숫자 범위/분포는 복권 성장 대상**(§7) — 상한↑(value 인플레이션) 또는 고숫자 가중치↑로 폭발력 보정.

### 4-2~4. 족보 평가 / 동점
- 동일 숫자가 **가장 많이 나온 case**가 최종값. 카운트 동점 시 **value 높은 쪽** 우선.
- 결과 dict(`HandEvaluator.evaluate(numbers, wild_count)`): `{ count, value, mult, name, groups }`. `mult = count² × value`(족보배율), `groups`=그룹 크기 내림차순(②족보 확장 판정용), 와일드 칸(`wild_count`)은 최대 그룹에 합류해 매칭 +wild_count.

## 5. 족보배율 / 데미지 연계

족보 결과는 곱연산의 **배율**로 쓰인다:
```
한 방 데미지  ≈  캐릭터 기본 공격력  ×  복권 족보배율(count·value 기반)
```
- 같은 숫자 많을수록·높을수록 배율↑, 9개 동일 = 잭팟. 정식 계수는 TBD(컨셉 §12).
- 적용 시점 = PC `attack` 종료 시([[전투 시스템 정리본]] §3-2).
- 복권 등급/배율 업그레이드가 이 배율 전체에 추가 보정(§7).

## 6. 출력 형식 (`NotificationManager.hand_result()`)
- 9칸 완료 시 화면 중앙 큰 텍스트. 형식 `{value} X {count} {!×count}` (예: 7×9 → `7 X 9 !!!!!!!!!`). 폰트·트윈은 [[UI 시스템 정리본]] §8.
- 스크래치는 카드 평가·`card_completed.emit`까지만 담당하고, 결과 표시는 `NotificationManager.hand_result(value, count, jackpot)`(autoload 토스트, "hand" 슬롯, 화면 중앙)가 책임진다.
- **잭팟(count ≥ 9)**이면 `NotificationManager.hand_result(..., jackpot=true)`가 결과 텍스트 아래에 금색 "JACKPOT" 태그 팝업을 추가로 표시한다.

## 7. 복권 성장 연계

스크래치 관련 성장 = **복권 성장 축**([[게임 컨셉 정리본]] §6):

| 성장 항목 | 효과 | 성격 |
|---|---|---|
| **자동 긁기 속도** | 방치 DPS(자동 진행 속도)↑ | 긴 텀 + **상한 O** |
| **긁기 범위(브러시)** | 수동 `brush_radius`↑ → 한 번에 넓게 긁힘 | 상한 O |
| **복권 배율 / 등급** | 족보배율 전체 보정↑ | 폭발력 |
| **잭팟·족보 확률 보정** | 높은 족보가 더 잘 뜸 | 운을 돈으로 |
| **숫자 범위** | `number_max`↑ → value 인플레이션 | 천장 확장 |

캐릭터 기본 공격력은 복권이 아니라 캐릭터 축 — 곱연산의 베이스. 트랙 수치·곡선·구매는 [[강화 시스템 정리본]].

## 8. 코드 위치 / 데이터

### 8-1. 코드 위치
| 파일 | 클래스 | 담당 |
|---|---|---|
| `scenes/scratch_card.tscn` | (씬) | anchor top-left 고정, 크기는 `game.gd`가 `configure()`로 명시 |
| `scripts/scratch_card.gd` | `ScratchCard` | 그리드/sub-cell 구축, 입력 처리, 셀 피드백, `card_completed`. `configure(grid_size)`로 빌드(웹 anchor size 0 회피) |
| `scripts/hand_evaluator.gd` | `HandEvaluator` | 9칸 → 결과 dict (static) |

### 8-2. 데이터 (튜닝 위치)
`scratch_card.gd` 상단 `@export`: `grid_cols/rows`(3/3 고정), `number_min/max`(1/9), `brush_radius`(30), `completion_threshold`(0.7), `center_complete_ratio`(0.5 — 가운데 영역 완성 OR 조건), `subdivisions_per_cell`(10), `cell_padding`(4). (잠금은 `game.gd`가 전적으로 소유하므로 §3-6, 카드 자체에는 잠금 시간 export가 없다.)

### 8-3. 영역 레이아웃
`scripts/scratch_card_layout.gd`(`ScratchCardLayout`)가 `ScratchCardArea`의 위치·크기·스케일 관리(`game.gd._ready`에서 적용). HEIGHT 240 / WIDTH 260 / SCALE 0.528 / X·Y_OFFSET 등. `TicketBackground`는 독립 노드(절대 좌표).

## 9. 확장 여지
- **자동 긁기 속도 업그레이드**(성장 핵심), **숫자 범위 확장**, **복권 등급/배율**, **잭팟 확률 보정** — §7.
- **그리드 크기 변경(4×4 등)**: 보류. 레이아웃·밸런스 리스크가 커서 당분간 3×3 고정(§2-2).
- **긁기 범위(브러시) 강화** — 구현됨(`brush` 트랙, [[강화 시스템 정리본]]). 특수 셀(고정 숫자·보너스)은 추후. 포커식 구분족보(페어·트리플·풀하우스 등)는 추후 유물(족보 확장)로 해금. 슬롯/라인/포커의 정식 그리드 채택은 폐기(매칭 그룹 정체성 유지). [[족보 스킬 시스템 정리본]] 참조.
