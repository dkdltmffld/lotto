# 전투 시스템

> 상위 컨셉은 [[게임 컨셉 정리본]]. 본 문서는 그 안에서 **전투 메커니즘 세부**(PC 상태·적·데미지·스테이지 스케일·연출)를 다룬다. 스크래치 입력 세부는 [[스크래치 시스템 정리본]], 경제·방치는 [[게임 컨셉 정리본]] §7~8.
>
> ✅ **2026-06-05 구현 완료:** 속도감 개선을 위해 전투를 **2레이어**로 전환 — **① 일반 공격(자동, 주기적) + ② 스크래치 = 스킬(강타/버스트)**. 기존엔 "스크래치 완료 시에만 공격"이라 그 사이 데드타임이 많아 체감이 느렸다. 자동 공격이 바닥 DPS를 깔아 항상 타격이 일어나게 하고, 스크래치는 "운으로 터뜨리는 강타"로 격상했다. 구현 위치는 §9.
>
> ✅ **2026-06-15 변경:** **`attack_speed`(공격속도) 강화 트랙을 폐지**하고 자동공격 속도를 **고정값**(`balance.yaml` `auto_attack.speed` = 3.3 초당 횟수 → 런타임 `Balance.AUTO_ATK_SPEED`)으로 전환. 옛 강화 트랙의 max값(0.8 + 0.1×25 = 3.3)을 **모두에게 기본 제공**한 것. 자동공격 DPS는 이제 **공격력(`attack`)으로만 성장**(속도는 고정). 2레이어 구조·데미지 공식·스크래치 스킬은 불변.

## 1. 개요

PC가 우측으로 진행하다 적을 조우하면 정지하고 전투한다. 전투는 두 갈래로 동시에 진행된다:

- **일반 공격(자동)**: 교전 중 **고정 주기**(`Balance.AUTO_ATK_SPEED` = 3.3 초당 횟수)마다 자동으로 발동하는 꾸준한 기본 타격. 입력 불필요(완전 방치 가능). 데드타임을 없애 속도감을 만든다.
- **스크래치 스킬(강타)**: 9칸 스크래치 완성 시 발동하는 **큰 버스트**. 운(족보)으로 데미지가 폭발하고, 보스·벽 돌파의 주역이자 잭팟 골드의 원천. 게임의 정체성(스크래치 복권)은 여기에 유지된다.

**일반 적도 PC를 약하게 공격하고, 10단위 보스는 치명적으로 공격한다** — PC HP가 0이 되면 그 블록 처음으로 돌아간다(§5). 적 처치 → 골드 → 성장 → 더 센 적(다음 스테이지)의 무한 루프.

## 2. 기본 작동

### 2-1. 플레이어 캐릭터 (PC)

PC는 화면 좌측에 존재한다. idle/run/attack은 항상 쓰이고, **attacked는 일반몹·보스 공격 모두에서**, **dead는 PC HP 0 시**(보스가 주원인, 일반몹 누적으로도 가능) 쓰인다.

- **기본 상태 (idle)**: 적 조우 후 정지 시. 액션 종료 후 복귀하는 기본 상태.
- **이동 상태 (run)**: 적 조우 전, 그리고 적 사망 후 다음 적을 향해 우측 이동.
- **공격 상태 (attack)**: **일반 공격(자동, 고정 주기) 또는 스크래치 스킬** 발동 시 진입. 1회 재생 후 idle 복귀. (개정: 자동 공격도 이 모션을 쓴다. 더미 단계는 공용, 추후 일반=가벼운 모션 / 스킬=전용 강타 모션으로 분리 가능.)
- **피격 상태 (attacked)**: 적에게 공격받을 때(보스·일반몹 공통). 1회 재생 후 idle.
- **사망 상태 (dead)**: PC HP 0 시(보스가 주원인, 일반몹 누적으로도 가능). 진행 중 모션·트윈 즉시 취소, dead 1회 재생 → 소폭 후퇴([[스테이지 시스템 정리본]] §5).

#### 상태 전이
- 게임 시작 → **idle**(짧게 출현) → **run**(우측 이동)
- 적 조우 → **idle**(정지, 전투 진입)
- 교전 중: **고정 주기(`Balance.AUTO_ATK_SPEED`)마다 attack(일반 공격)** → idle, **스크래치 완성 시 attack(스킬)** → idle (적이 살아있는 한 반복)
- 웨이브 내 적 사망(뒤에 대기 적 있음) → **즉시 run**(다음 적까지 PC가 짧게 전진). 카드 잠금·리셋 없음 = 연속 조작
- 웨이브 전멸(스테이지 진행 1) → 짧은 대기 → **run**(다음 웨이브까지 이동). 이때 카드 잠금·리셋([[UI 시스템 정리본]] §7-2)
- 적 공격(일반몹·보스 공통) → **attacked** → idle / PC HP 0 → **dead** → 소폭 후퇴(§5)

#### 상태 → 모션 매핑
| 상태 | 모션 | 사용 |
|---|---|---|
| 기본 | `PC_idle` | 항상 |
| 이동 | `PC_run` | 항상 |
| 공격 | `PC_attack` | 항상 (일반 공격 + 스킬 공용, 추후 분리 가능) |
| 피격 | `PC_attacked` | 일반몹·보스 공격 시 |
| 사망 | `PC_dead` | PC HP 0 시 |

**자산**: `assets/sprites/player/PC_*.png` (256×256 프레임, 프레임 수 = width/256 자동 계산). **매핑 관리**: `scripts/player_data.gd`의 `PlayerData.ANIMATIONS`.

### 2-2. 몬스터

월드 좌표에 고정, 이동하지 않는다. PC가 우측으로 이동함에 따라 화면이 스크롤되며 우측 바깥에서 드러난다. PC가 조우 위치에 도착해 정지하면 전투가 시작되고, 처치하면 다음 몬스터로 이동을 재개한다. **잡몹은 같은 종류 2~4마리 웨이브로 대형 등장**(2026-06-09) — 맨 앞 1마리와 교전(나머지는 뒤에서 대기), 처치하면 **PC가 짧게 전진**(run 재사용)해 다음 적과 교전, 웨이브 전멸 시 다음 웨이브로 이동. **맨 앞 1마리만 PC 공격**, 마리당 골드, 웨이브 = 스테이지 진행 1. (보스·튜토리얼은 1마리.)

- **일반 몬스터도 PC를 공격한다** — 단 **보스(10단위)보다 빈도·데미지가 현저히 낮다**(찔끔찔끔, 위협은 작게). 치명적인 건 여전히 보스(§5). 일반몹은 약한 누적 압박으로 **생존력(HP) 성장에 의미**를 더한다.
  - 공격 수치: 일반몹 `MOB_ATTACK_INTERVAL/MOB_ATK_BASE/MOB_ATK_GROWTH/MOB_ATTACK_WINDUP`, 보스 `BOSS_*` (`balance.gd`). 일반몹 데미지 ≈ 보스의 ~1/6, 간격 ↑. 수치 잠정.
  - **회복**: 보스 진입 시 풀충전 + **PC 사망→소폭 후퇴 시 풀충전** + **강화 `hp_regen`(체력 재생)으로 초당 자동 회복**(사망 연출·튜토리얼 중 제외, HP가 가득이면 스킵). hp_regen은 **보스전 중에도 끄지 않는다**(현행 `in_boss` 게이트 없음 = 의도된 동작으로 확정) — 회복이 **찔끔 수준**이라 보스 순간딜이 이를 압도하므로 보스전 ON이어도 무한생존 위험이 없다. 블록 내(1~9 스테이지)엔 **hp_regen 회복을 초과하는 피해만 누적**(보스까지 버티기). PC HP바는 **항상 표시**. 설계 의도 상세 §3-6.
- **외형 = cosmetic (무작위 변종)**: 스탯은 스테이지 공식(§5)이 담당하므로 스프라이트는 스탯과 무관. **스폰 시 외형 변종을 무작위 선택**(일반몹·보스 공통, 스탯·타이밍 불변). 구조·정렬 상세 [[스테이지 시스템 정리본]] §8.
- `AnimatedSprite2D` 사용(가로 스트립 **폭 256 고정, 높이는 시트별 가변** — 발끝 하단 정렬). 피격 시 빨간 modulate 플래시.
- **자산**: `assets/sprites/enemies/<id>/<id>_idle.png`·`<id>_attack.png` (변종 폴더, 현재 `mon_001`~`mon_003`).

## 3. 전투력 / 데미지 (2레이어)

### 3-1. 두 레이어 개요
```
일반 공격(자동) 데미지 ≈ 캐릭터 공격력 × 자동공격 계수        ← 고정 주기마다 반복 (바닥 DPS)
스크래치 스킬 데미지   ≈ 캐릭터 공격력 × 복권 배율 × 족보배율   ← 9칸 완성마다 (운 버스트)
```
- **캐릭터 공격력(attack)**: 골드로 키우는 베이스. **두 레이어 모두**의 바닥을 올리는 중심 스탯. 실제 적용값 = 강화 `attack` × (1 + 장착 무기 보너스)(`game.gd _attack_power`, [[장비 시스템 정리본]]).
- **자동공격 속도(`Balance.AUTO_ATK_SPEED`)**: 일반 공격의 발동 주기. **고정값**(= 3.3 초당 횟수, `balance.yaml` `auto_attack.speed`) — **강화 트랙 폐지(2026-06-15)**. 속도는 모두 동일, 자동공격 DPS는 공격력으로만 성장 (§4).
- **복권 배율(card_mult) · 족보배율**: 스크래치 스킬 버스트 전용. 같은 숫자 많을수록·높을수록 큰 폭발. 족보 세부 [[스크래치 시스템 정리본]] §4~5.

### 3-2. 일반 공격 (자동) — (2026-06-05 적용)
- 적과 교전(idle) 중 **고정 주기(`Balance.AUTO_ATK_SPEED` = 3.3 초당 횟수)마다** 자동 발동. 입력 불필요.
- 데미지 = `공격력 × AUTO_ATK_COEF`(기본계수, 잠정 1.0). 한 방은 작지만 **끊임없이** 들어가 데드타임을 없앤다.
- 잡몹은 일반 공격만으로도 충분히 처치되도록(빠른 템포) 계수·자동공격 속도를 잡는다. **속도는 고정**이므로 잡몹 처치 템포 조정은 계수·적 HP로 한다.

### 3-3. 스크래치 스킬 (강타) — 기존 공격의 격상 (2026-06-05 적용)
- 9칸 완성 시 발동. **총 데미지 = `공격력 × 복권 배율 × 족보배율`**(= 큰 버스트, 변함 없음).
- ✅ **(2026-06-17) 스킬 = 다타격(연타) 연출.** 한 방 큰 숫자 대신 **족보 count만큼 연속 타격(다다다닥)** — 데미지 플로터가 빠르게 여러 번 뜬다. **타수 = 족보 count**(페어 2타 ~ 나인 9타), **한 타 데미지 = 총 데미지 / 타수**(누적 반올림 → 합은 총 데미지와 동일). 즉 기존 족보배율 `count²×value` 중 **count 한 겹을 "타수"로 시각화**한 것 — **총딜·밸런스는 그대로**(쪼개기). 높은 족보 = 타수↑ + 한 타↑. 타격 간격 = `game.gd SKILL_HIT_INTERVAL`(0.05초, 튜닝 노브).
- **잭팟(9칸 동일)** = 최대 버스트 + **보너스 골드**(§6) + **웨이브 전체 연타(AoE)**(`AOE_MIN_COUNT`=9 이상 족보는 살아있는 모든 적에 각 타를 동시 적용 — 다타격 × 무리 전체). 가장 짜릿한 순간.
- 보스 등 높은 HP는 일반 공격만으론 느리거나 못 잡게 설계 → **스크래치 버스트가 벽 돌파의 주역**. 스크래치가 여전히 게임의 주인공.

### 3-4. 스킬 발동 방식 = 상시 능동 + 방치 자동발동 (확정)
- **능동**: 플레이어가 직접 긁어 9칸 완성 → **즉시 스킬 발동(쿨다운 없음)**. 빠르게 긁을수록 스킬이 자주 터진다 = throughput 보상(운은 동일).
- **방치**: `auto_speed`(자동 긁기 속도) 주기로 카드가 자동 완성 → **스킬 자동 발동**. 즉 auto_speed의 의미가 "**방치 시 스킬 자동발동 주기**"로 전환된다(트랙 유지).
- 정리: **일반 공격(자동)은 항상 바닥을 깔고**, 그 위에 스크래치 스킬이 **능동(빠름)/방치(느림)**으로 얹힌다.

### 3-5. 적용 시점 (구현 관점)
- **일반 공격**: 고정 자동공격 속도(`Balance.AUTO_ATK_SPEED`) **타이머 기반으로 모션을 발동**하되, **데미지·이펙트는 `attack` 모션 종료 시점에 적용**한다(2026-06-09 변경 — 한 방 처치 시 전진(run)이 스윙을 끊지 않게 스킬과 동일하게 지연 적용). ⚠️ 스윙이 진행 중이면 다음 자동 공격을 시작하지 않으므로(중복 방지) **실효 자동공격 속도는 사실상 attack 모션 길이에 캡**된다 — 더 빠르게 하려면 `player_data.gd` attack 모션 speed를 올린다.
- **스크래치 스킬**: 현행 유지 — PC `attack` 애니메이션 종료 시점에 버스트 데미지 + 이펙트(즉시 타격, 발사체 없음).
- 두 레이어가 겹칠 수 있다 → 데미지는 각각 누적. 모션은 한 번에 하나(스킬 발동 시 스킬 모션 우선). 더미 단계 단순화 허용.
- 확장 여지: 향후 발사체/다중 스킬이 추가될 수 있으므로 공격 처리는 발사체 유무 선택 가능한 구조 유지.

### 3-6. 생존 (보스전)
- 보스전은 **공격 vs 생존의 레이스**: 내 총 DPS(일반 공격 + 스킬 버스트)로 보스를 잡는 속도 vs 보스 공격으로 내 HP가 깎이는 속도.
- **PC HP / 방어 = 캐릭터 생존력 성장 축**([[게임 컨셉 정리본]] §6). 키우면 더 오래 버텨 더 높은 보스를 잡는다.
- **PC 최대 HP = 강화 `hp` × (1 + 장착 방어구 보너스)**(`game.gd _max_hp`, [[장비 시스템 정리본]]).
- **HP 자동 회복(`hp_regen` 트랙, 초당)**: 깎인 HP를 매 프레임 메우는 생존 유지축(사망 연출·튜토리얼 중 제외). **보스전 중에도 작동**(현행 `in_boss` 게이트 없음 = 의도된 동작으로 확정).
- **역할 = "찔끔 유지형"**: hp_regen은 **일반몹의 찔끔 피해만 상쇄**하고, 그를 **초과하는 큰 피해·연타는 여전히 누적**된다. 따라서:
  - **HP 풀(`hp` 강화 트랙) 성장이 보스 생존의 진짜 축**으로 유지된다 — hp_regen은 보스의 큰 데미지를 따라잡지 못하므로 보스를 오래 버티려면 결국 최대 HP를 키워야 한다.
  - 블록 내 **'누적 압박'(=HP 업글 동기)도 보존**된다 — 일반몹 누적이 회복으로 완전 상쇄되는 게 아니라, 회복을 초과하는 분만 남아 보스까지 압박이 이어진다.
  - 회복이 작아 **보스전 ON이어도 보스 순간딜이 회복을 압도** → 무한생존 위험 없음.
- 일반몹 공격이 약해 위협은 작지만 HP는 **블록 내(1~9 스테이지)에서 hp_regen 회복을 초과하는 분만 누적 소모**되며, **보스 진입 시(및 사망→소폭 후퇴 시) 풀충전**된다.

## 5. 스테이지 / 보스 / 사망 (전투 관점)

스테이지·블록 구조, 적 HP·골드 스케일링 공식, 보스 게이트, 사망→소폭 후퇴의 전체 규칙은 **[[스테이지 시스템 정리본]]** 참조. 전투에서 중요한 점만:

- **일반 적**: 일반 공격(자동)만으로도 **항상 처치**(빠른 템포), 스크래치 스킬이 가속. 처치 시 골드(§6).
- **보스(10·20·30…)**: 치명적 공격 + 높은 HP. 일반 공격 DPS만으론 부족하게 설계 → **스크래치 버스트(특히 잭팟)로 돌파**. PC HP 0 → `dead` 후 몇 스테이지 소폭 후퇴(`DEATH_SETBACK`, 블록 첫이 바닥선 — 골드·강화 유지, HP 풀충전).
- 적 HP가 내 총 DPS를 앞지르면 처치가 느려지고(soft 벽), 보스를 못 잡으면 진행이 막힌다(hard 벽) → 업그레이드 동기.

## 6. 골드 / 보상

- 적 처치 시 **골드** 획득(스테이지 비례, §5). **잭팟·고족보(스킬) 시 보너스 골드**.
- 골드는 **강화(캐릭터/복권/저장소 업그레이드) 전용** 통화([[게임 컨셉 정리본]] §7).
- ✅ **2026-06-08 추가:** 재화는 골드 외에 **장비 가챠용 다이아(별도 통화)**가 추가됨. 통화는 `BackendService`의 `get/add/spend_currency(name)`로 일반화됨. 상세는 [[재화 정책 초안]]/[[장비 시스템 정리본]].
- ✅ **2026-06-17 추가 — 보스 첫 클리어 = 유물 가루(dust) 획득:** 보스 처치 보상에 가루 지급이 추가됨. `Balance.boss_dust(stage)=per_boss_base(50)+per_boss_step(10)×(블록인덱스-1)`(비보스 0, 가챠 비용 고정이라 완만 선형), `backend.grant_boss_dust(stage)`가 세이브 키 `dust_boss_max`로 **첫 클리어만** 지급(재파밍 0, `DEATH_SETBACK` 후퇴 무관). 지급 시 `NotificationManager.reward` + `Events.currency_changed` + reward 효과음. 오프라인 가루 없음. 수치 더미.
- ⚠️ **다이아는** 현재 퀘스트·우편함에서 **임시 더미로 지급**될 뿐(치트 포함)이고, **가루는 보스 첫 클리어가 정식 채널**(공급 수치만 더미). 둘 다 정식 획득 곡선·BM·천장은 미설계.
- **오프라인**: 떠난 시점의 **현재 스테이지를 고정 farming**해 골드 누적. 누적 상한·자동 긁기 속도 상한은 컨셉 §8.

## 7. 시각 · 연출

### 7-1. 데미지 플로터
- **일반 공격/스킬**(`n`): 적/보스 머리 위. **색상 = 붉은 계열**(2026-06-17 노랑→빨강 변경): 자동 = `DAMAGE_FLOATER_OUTGOING`(진한 빨강), 스킬 = `DAMAGE_FLOATER_SKILL`(밝은 빨강). 피격(incoming)은 연한 붉은색이라 톤으로 구분. **스킬 버스트는 더 크게/강조**(✅ 구현 — `big=true`: font36·스케일 팝·더 높이 상승 / 자동은 작게) + **다타격이라 한 번에 여러 개가 다다다닥**(타수=족보 count).
- **피격**(`-n`): 적(일반몹·보스 모두 — 맨 앞 1마리)이 PC를 때릴 때 PC 머리 위, 색상 `DAMAGE_FLOATER_INCOMING`.
- HUD 소속. 색상은 `scripts/ui_palette.gd`.

### 7-2. 연출 차등 (속도감 핵심)
- **일반 공격**: 가벼운 타격(작은 burst + 작은 플로터). 자주 일어나므로 과하지 않게.
- **스크래치 스킬**: 큰 임팩트 버스트 + 족보 결과 텍스트 + **화면 흔들림**(✅ 구현 — `Effects.screen_shake`: 잭팟 ≥9 화면 전체 강하게 / 고족보 ≥4 전투영역 중간 / 그 외 약하게) + **고족보 컷인**(✅ 별도 구현, [[스크래치 시스템 정리본]]/족보) + 잭팟 결과 태그. "터졌다" 느낌.
- 추후: 히트스톱 등 juice 검토.

### 7-3. 체력 표시 / 등장·사망
- 적/보스 머리 위 체력바. PC 체력바 항상 표시.
- 등장: 화면 스크롤 자연 등장. 적 사망: 폭발(코어+파편, 더미). PC 사망(보스전): dead 모션 후 블록 복귀(§5).

## 9. 구현 영향 (적용 완료)

- **`game.gd`** (적용 완료):
  - **일반 공격 루프**: idle(교전) 중 `_process`가 **고정 주기(`Balance.AUTO_ATK_SPEED`, 간격 = 1/aps)** 타이머로 `_auto_attack()` 발동(2026-06-15 — `Upgrades.value("attack_speed")`에서 고정값으로 변경, 강화 트랙 폐지) → 모션만 시작하고 데미지(`공격력×Balance.AUTO_ATK_COEF`)는 `_auto_pending`/`_auto_pending_damage`에 보관해 **attack 모션 종료(`_on_player_attack_completed`)에서 적용**(2026-06-09 — 스킬과 동일 지연 적용으로 처치→전진이 스윙을 끊지 않게). 스윙 진행 중(`_skill_pending`/`_auto_pending`)이면 새 자동 공격을 시작하지 않는다. 적 처치 시 동일 처치 경로(`_on_enemy_died`).
  - **스크래치 = 스킬**: `_on_card_completed`/`_on_player_attack_completed`의 버스트 데미지 로직이 스킬을 담당. 자동공격과 구분하려고 `_skill_pending`/`_auto_pending` 플래그를 둬, attack 모션 종료 시 스킬이면 버스트, 자동이면 일반 데미지를 적용한다. **스킬 = 다타격(`_skill_multihit`, 2026-06-17)**: 타수=족보 count, 한 타=총딜/타수(누적 반올림), `SKILL_HIT_INTERVAL`(0.05s) 간격 await 연타. 단일=앞 1마리 / **잭팟(count ≥ `AOE_MIN_COUNT`=9)=무리 전체 연타**. 시퀀스 동안 `_aoe_active`(개별 처치=골드·연출만) + `_skill_resolving`(자동공격·재진입 억제, `_enter_idle/run`에서 안전 해제), 끝에 `_resolve_wave_after_aoe`로 대형/스테이지 일괄 정리. **튜토리얼은 스크립트 단일 타격**(다타격 제외). 구 `_skill_aoe` 폐기·`_skill_multihit`로 통합.
  - 교전 시작/종료(idle 진입·이탈, 사망, run)에서 자동 공격 타이머·`_skill_pending` 상태 정리.
- **데이터** (반영 완료): `data/src/balance.yaml`에 `auto_attack.coef` (= `Balance.AUTO_ATK_COEF`, 현재 1.0) + `auto_attack.speed` (= `Balance.AUTO_ATK_SPEED`, **고정 3.3 초당 횟수**). **`attack_speed` 강화 트랙은 `upgrades.yaml` tracks·order에서 삭제됨(2026-06-15)** — 옛 트랙(base_val 0.8/per_level 0.1/max_level 25)의 max값(3.3)을 balance 고정값으로 이전. 변환(`build_data.gd`)으로 `*.json` 반영됨.
- **`player_controller.gd`** (적용 완료): 자동 공격용 `play_auto_attack()` 추가(가벼운 잽). 추후 전용 모션 분리 시 매핑 추가 가능.
- **밸런스 재튜닝** (진행 중): 자동 vs 스킬 비중, 보스 HP/공격(자동 DPS 추가분 반영), 자동공격 고정 속도(`AUTO_ATK_SPEED`)·계수 적정값. 수치는 잠정.
- **튜토리얼**: 1단계 "긁어서 공격" 메시지에 자동 공격 존재를 반영할지 검토(긁기=강한 스킬로 안내).
